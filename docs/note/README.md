# note の紹介記事（投稿ランチャー / XXX_automatic）

このフォルダの中身は、note の連載「教室で使えるかもしれないもの作り」に貼るためのものです。

```
docs/note/
├── xxx-automatic-note-article.md   記事本文（そのまま note に貼れる形）
├── images/                          実際に操作して撮った画面 20点
└── README.md                        このファイル
```

本文は 8,026字（画像の記法を除く、空白を除いて数えたもの）、画面は 20点です。

---

## 貼るまえに直すところ

**連載番号が `#◯` のままです。** 1行目のタイトルの `#◯` を、実際の番号に直してください。
番号は推測で埋めていません（間違えると連載が壊れるため）。

それ以外は、そのまま貼れる状態にしてあります。

## note に貼る手順

1. note の新規記事を開きます。
2. `xxx-automatic-note-article.md` の1行目（`# 教室で…`）を、note のタイトル欄に貼ります。
   先頭の `# ` は外してください。
3. 2行目以降を本文欄に貼ります。`##` の見出しはそのまま貼れば note の見出しになります。
   note は見出しから目次を自動で作るので、順番は変えないほうが読みやすくなります。
4. `![…](images/xx-….png)` の行は note では画像になりません。**その位置で画像を1点ずつ手で上げてください。**
   ファイル名は下の対応表のとおりです。
5. 画像のすぐ下にある1行（「今日の下書き。日付と型と…」など）は、**キャプション欄に移してください。**
   本文に残すと、画像の説明が本文の中に混ざって読みにくくなります。
6. 最後の `## 🏷 ハッシュタグ` の行は本文から外し、**note のハッシュタグ欄に入れてください。**
   12個あります。
7. はじめにの節に URL が2か所あります。note に貼るとカード表示になります。そのままで問題ありません。

## 文体について踏襲したもの

`config/note-style.json` と `scripts/lib/note-lint.mjs` の基準に合わせてあります。
機械の検査（`lintArticle`）は問題なしで通っています。

- 太字・斜体・表・区切り記号（`→` `／` `▲` `▶` `※`）を使っていない
- 箇条書きは【利用者向け】の手順だけ
- 専門用語を日常の言葉に置きかえている
  （「API」「リポジトリ」「ローカルストレージ」などは使わず、
  「自動投稿のつながり口」「ファイルを置いてある場所」「その端末のなかだけに残ります」と書いている）
- 絵文字は見出しだけ
- 子どものことは「子どもたち」、読み手は「先生」
- 見出しは決まった6本＋あいだに2本（🕒 と 📚）。足せるのは2本までなので上限いっぱい
- 本文 7,000〜9,000字の範囲に収めている（8,026字）
- 教室での出来事を実体験として書いていない。書いたのは「こうなればいいと思って作った」まで

**授業で実際にどうだったかは書いていません。** そこは公開する前にご自身で足してください。
記事の中でも、その一文を足すのが人の仕事だと書いています。

## 撮り直すときの手順

```bash
npm i --no-save playwright
node <スキル>/scripts/serve.mjs docs 4180 /XXX_automatic/     # 別ターミナル
node <スキル>/scripts/capture.mjs .tmp-shots/shots.mjs \
  --base http://127.0.0.1:4180/XXX_automatic/ --out docs/note/images
```

シナリオ（`shots.mjs`）は `.tmp-shots/` に置いて、納品時に消しています。
`node_modules` の解決の都合でリポジトリの中に置くことになるためです。
作りなおすときに要る点だけ、ここに残しておきます。

- 画面の大きさは 390×940。ホーム・今週・一覧のように縦に長い画面は、
  撮る直前に `resize(390, 1500〜1900)` して1枚に収めています。
- タブや節を切り替えたら 1,200ms 前後は待ちます。開いた直後に撮ると、
  まだ出ていないカードを撮り落とします。
- ［…］は開いたままだと一覧が読みにくいので、次の画面に移る前に閉じます。
- ［つくる］のアプリ検索は `setInput('.make__search', '計算')` で絞れます。
- タブごとに `open()` を分けます。［記録］は［投稿した］を押したあとの状態なので、
  同じ画面を使いまわすと前の操作が残ります。

撮影のときに2つだけ細工をしています。どちらも**画面に写るものを偽っていません**。

1. **端末の日付を 2026-08-10（月）7:10 に合わせています**
   （Playwright の `context.clock.setSystemTime()` を呼んでから再読み込み）。
   撮影日（8/9）は翌週ぶんが用意された直後で、［今日］が空でした。
   空の画面を並べても伝わらないので、この週の投稿が始まる日に合わせています。
   出ているのは、その日に本当に用意されている下書きです。
2. **`raw.githubusercontent.com` の画像を、手もとに落としたものから返しています**
   （`context.route()` で差しかえ）。撮影した環境が外に出られなかったためです。
   落としたのは本番と同じ URL のもので、写っているのは本物です。
   外に出られる環境で撮るなら、この差しかえは要りません。

## 公開の前に

**この記事とは別に、UI の修正が1件入っています。**
撮影中に見つけたもので、`fix(ui): ［…］と画像の一覧が閉じられなかった（hidden が効いていない）`
というコミットです。記事の画面はこの修正が入った状態で撮ってあるので、
**修正を先に公開してから記事を出してください。** 順番が逆になると、
記事の画面と本番の画面が食い違います。

内容は次のとおりです。

- カードの［…］が最初から開いたままで、毎日押す2つとたまに押す4つが同じ大きさで並んでいた。
  押しても見た目が変わらないので、何も起きないボタンにも見えていた
- note の［画像を1枚ずつ渡す］が、一度開くと閉じられなかった

どちらも `.more` と `.shots` にクラス側で `display` を書いていて、
`hidden` 属性（UA の `display:none`）を上書きしていたためです。
`tools/measure-ui.mjs` に、`hidden` が効いていない要素をあげる検査を足してあります。
